# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Visual design (user decisions of 2026-11-05)
- The user asked for a redesign in the designer's own taste, then clarified: a 主题 must be a different *style* (layout, shape, material), each with its own colours, following Apple's design language. Colour-only themes are not enough.
- Look = 主题 × 颜色 × 外观. 主题: 玻璃 (default; frosted glass sheet over a wallpaper painted from the colour), 小组件 (iOS home-screen widgets grid with Activity-style rings), 纸墨 (warm paper and ink, the 1.5 design). 颜色: Apple's eight accents (蓝 紫 粉 红 橙 黄 绿 石墨); 纸墨 renders them as mineral pigments. 外观: 浅色 / 深色 / 自动. Default 玻璃 · 蓝 · 自动.
- Settings fields `theme` (style id), `themeColor`, `appearance`. `normalizeLook` upgrades every older value (1.x palettes and 1.5 palettes become 纸墨 in the nearest colour; untouched defaults become the new default); never drop that map.
- One markup for all 主题; layout differences are CSS under `[data-style=…]`. Tokens are attribute-scoped in `src/themes.css` so previews can carry their own `data-style/data-color/data-scheme`. Keep button labels and text ≥ 4.5:1 (see `--accent-button`, `--accent-text`, `--on-accent`).
- Rules: one hero figure (today's income); accent marks only what is live (status dot, hour cells, rings, goal track); labels and values use text tokens.
- Keep these hooks for the desktop floating widget: `.income-value` (plain number text), `.countdown > span` ×3, `.status.<state>`, the first `[role="progressbar"]` with `aria-valuenow`, `.settings-button`.
- The embedded font is a subset; after adding UI text run `python scripts/subset-font.py` (uses the OFL Noto Sans SC that Windows ships).
- QA: `qa.html?theme=<style>&color=<id>&appearance=<light|dark>&at=<ISO>&settings=<json>` (frozen clock, in-memory storage) and `qa-themes.html?color=<id>` (every 主题, light and dark).
- Deliveries: keep only the newest version's files in the user's folder; old versions go to the Recycle Bin, not kept side by side.
- `window.workCheerWindow` exists only in the Windows app (frameless window): `App.jsx` then draws `WindowBar` and makes the empty page background a window drag region. The website and offline page never show it; `qa.html?desktop=1` stubs it for checks.

## 1.10 themes (user request of 2026-11-13)
- The user asked for a few more themes in the designer's own taste, naming 像素 and 赛博朋克 as examples (“都可以”). That lifts the 2026-11-05 “follow Apple's design language” rule for new themes: a 主题 must still be a different style (layout, shape, material), but it may be any coherent visual language. 玻璃 / 小组件 / 纸墨 are unchanged and 玻璃 · 蓝 · 自动 stays the default.
- Added: 像素 `pixel` (8-bit status window: notched pixel frames, dot-matrix numerals, stat rows with dotted leaders), 赛博朋克 `cyber` (chamfered neon HUD; every colour has a clashing partner in `--accent-2`), 千禧 `y2k` (late-90s window: title bar, group boxes, bevels, block progress bars, SimSun + Tahoma), 黏土 `clay` (pressed-in pillows, puffed controls), 液晶 `lcd` (date, income and countdown share one LCD with ghost segments; the dark appearance is a glowing VFD).
- Their structure is in `src/styles-more.css`, their tokens at the end of `src/themes.css` (after the colour rules, so a theme can restate an accent token). Miniatures are styled only through `.style-preview[data-style=…]`: the settings dialog nests every theme's preview under the current theme's `<html>`, so a theme rule that reached `.mini-*` would repaint all of them.
- `public/fonts/wc-pixel.woff2` and `wc-lcd.woff2` hold numerals drawn for this project by `python scripts/make-display-fonts.py` (byte-identical on every run, no third-party licence). 像素 numerals must be set at multiples of 10px (one em is ten dots). Chinese text in 像素 stays Noto Sans SC; a real CJK pixel font would mean a download and a licence review, so ask the user first.
- Hooks added for these themes: `data-ghost` on `.income-whole`, `.income-fraction`, `.countdown > span`, `.clock` and `.day-percent` (the same text in 8s, for LCD ghost segments; text content is unchanged, so the floating-widget hooks above still hold) and `--goal` (0–1) on `.goal-track span`, which the base CSS turns into `scaleX` and a theme may use as a width.
- The tokens the desktop floating widgets read (`--card --text --muted --line --accent --accent-2 --accent-text`) must resolve to plain sRGB — hex, `rgb()` or `color-mix(in srgb, …)`. The lite edition parses them natively and cannot read `oklab()`.
- More QA pages: `qa-states.html?theme=<style>&width=620|375|320` (one theme in ten states: before, break, paused, finished, day off, long goal name, 5/6/7-digit amounts) and `qa-themes.html?styles=a,b&appearance=light&columns=<n>`. Read colours with transitions frozen, or a running transition reports the previous look.
